# SchoolTouch — School Management System

SchoolTouch is a school-management project collection with a static website prototype and a MERN-based application. It brings together the UI work and the full-stack implementation in one repository for easier review.

## Project structure

- `schoolTouch-html-css/` — HTML, CSS, and JavaScript website prototype with school dashboards and pages.
- `SchoolTouch-Full-Stack/SchoolTouch-main/` — MERN full-stack SchoolTouch application. See the README inside this folder for its setup instructions.
- `CURD-operation-of-School-Touch-main/` — focused CRUD implementation. See its included project files and README for details.

## Features represented

Depending on the implementation, the project includes pages and workflows for school roles such as admin, teacher, student, and parent, along with dashboards and school operations such as attendance, timetables, fees, homework, and results.

> The static prototype and full-stack application are separate implementations. A UI page does not necessarily mean that its workflow is connected to a live API or database. Verify each feature in the relevant application before treating it as fully functional.

## Tech stack

- **Frontend prototype:** HTML, CSS, Bootstrap, JavaScript
- **Full-stack application:** MERN stack (MongoDB, Express.js, React, Node.js)
- **CRUD version:** see the implementation and setup instructions in its folder

## Getting started

### Static website

1. Open `schoolTouch-html-css/`.
2. Open its `index.html` in a browser, or use VS Code Live Server.

### MERN application

1. Open `SchoolTouch-Full-Stack/SchoolTouch-main/`.
2. Read the README and follow the client/server setup steps provided there.
3. Configure the required environment variables locally. Do not commit real secrets or credentials.

### CRUD implementation

Open `CURD-operation-of-School-Touch-main/` and follow the instructions provided with that version.

## Project status

This repository combines multiple versions of SchoolTouch for convenient access. Run and test each version independently; authentication, persistence, API connections, and other workflows should only be described as functional after verification.
